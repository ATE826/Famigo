# Актуализация ценностного предложения

## Ценностное предложение

Для семей и пар в ситуации, когда повседневные задачи — бюджет, продукты, события, домашние дела, местоположение и общение — распределены между несколькими разными приложениями, наше решение обеспечивает единое цифровое пространство для совместной организации семейной жизни, улучшая удобство взаимодействия и снижая необходимость переключаться между различными сервисами по сравнению с использованием отдельных приложений для каждой задачи, при условиях, что основные функции доступны в одном сервисе, а подключение членов семьи происходит быстро и без сложной настройки.

## Тезисы

**Единое пространство** — Семья получает доступ к бюджету, календарю, продуктам, домам, местоположению и общению в одном приложении вместо использования нескольких отдельных сервисов.

**Связь между функциями** — Информация из разных разделов может использоваться совместно: информация о приобретенных продуктах может быть связана с семейным бюджетом, а событие — с участниками, местом, напоминанием и уведомлением.

**Совместное управление** — Члены семьи получают возможность одновременно работать с общей информацией, а изменения становятся доступны другим участникам семейной группы.

**Freemium-модель** — Основные функции доступны бесплатно, а расширенные возможности, включая геолокацию, создание событий, увеличение количества участников и дополнительные интеллектуальные функции, предоставляются премиум-пользователям.

# Декомпозиция ценности в пользовательский сценарий

## Основной пользовательский сценарий

1. **Триггер** — Семья сталкивается с необходимостью организовать повседневные задачи: запланировать событие, распределить расходы, добавить информацию о приобретенных продуктах или узнать местоположение члена семьи.

2. **Вход пользователя** — Пользователь открывает веб-приложение Famigo и авторизуется или регистрируется.

3. **Создание семейной группы** — Пользователь создаёт семейную группу и получает возможность пригласить других членов семьи.

4. **Подключение членов семьи** — Члены семьи присоединяются к общей семейной группе и получают доступ к совместным разделам приложения в соответствии со своими правами.

5. **Работа с семейным пространством** — Пользователь открывает необходимый раздел: бюджет, календарь, продукты, дом, карту или чат.

6. **Ключевое действие: управление семейными данными** — Пользователь создаёт расход, добавляет информацию о продукте, создаёт событие, добавляет информацию о доме или отправляет сообщение в семейный чат.

7. **Синхронизация** — Изменения сохраняются и становятся доступны другим участникам семейной группы.

8. **Связь функций** — Данные используются в связанных разделах. Например, информация о приобретенном продукте может быть связана с расходом семейного бюджета, а событие может содержать место, участников и напоминание.

9. **Получение результата** — Члены семьи видят актуальную информацию в одном общем пространстве и могут принимать решения без необходимости использовать несколько разных приложений.

10. **Завершение** — Повседневная задача решена, а информация остаётся доступной другим членам семьи для дальнейшего использования.

## Альтернативный сценарий: Ошибка — пользователь не имеет доступа к функции

1. **Триггер** — Пользователь пытается воспользоваться функцией, доступной только премиум-пользователям.

2. **Проверка доступа** — Система определяет тип аккаунта пользователя.

3. **Ограничение** — Система блокирует использование премиум-функции.

4. **Сообщение** — Пользователю отображается понятное сообщение о необходимости премиум-доступа.

5. **Действие пользователя** — Пользователь продолжает использовать доступные бесплатные функции или переходит к оформлению премиум-подписки.

6. **Результат** — Пользователь не блокируется полностью и продолжает пользоваться семейным пространством.

---

## Альтернативный сценарий: Учет приобретенного продукта

1. **Триггер** — Член семьи приобретает продукт для дома.

2. **Действие пользователя** — Пользователь открывает раздел продуктов или холодильника соответствующего дома.

3. **Добавление продукта** — Пользователь указывает название продукта, количество, категорию и при необходимости срок годности.

4. **Синхронизация** — Информация о продукте появляется в общем пространстве дома и становится доступна другим членам семьи.

5. **Фиксация покупки** — Пользователь может указать, что продукт был приобретен, чтобы остальные члены семьи видели актуальное состояние продуктов.

6. **Связь с бюджетом** — При необходимости приобретение может быть связано с расходом семейного бюджета.

7. **Результат** — Члены семьи видят актуальную информацию о продуктах, находящихся дома, и могут понимать, какие продукты уже были приобретены.

---

## Альтернативный сценарий: Создание события

1. **Триггер** — В семье появляется необходимость запланировать совместное событие.

2. **Действие пользователя** — Пользователь открывает общий календарь.

3. **Создание события** — Пользователь указывает название, дату, время и необходимые параметры события.

4. **Добавление участников** — Пользователь выбирает членов семьи, которые должны участвовать в событии.

5. **Уведомление** — Система уведомляет участников о предстоящем событии.

6. **Результат** — Все участники семьи видят событие в общем календаре и могут заранее подготовиться.

# Нефункциональные требования

1. **Производительность (время отклика)**

   Время отклика интерфейса не должно превышать 2 секунд для 95% стандартных запросов.

   Основные страницы приложения должны загружаться не более чем за 3 секунды при нормальном интернет-соединении.

   Пользователь должен получать визуальную обратную связь после выполнения действий: добавления расхода, продукта, события или сообщения.

2. **Доступность интерфейса**

   Сервис должен работать в современных версиях Chrome, Safari, Firefox и Edge.

   Интерфейс должен быть адаптирован под мобильные устройства, планшеты и компьютеры.

   Основные функции должны быть доступны без необходимости использовать только один тип устройства.

3. **Безопасность и приватность**

   Доступ к семейным данным должен предоставляться только участникам соответствующей семейной группы.

   Финансовая информация, сообщения и данные о местоположении не должны быть доступны посторонним пользователям.

   Доступ к геолокации предоставляется только после разрешения пользователя.

   Пользователь должен иметь возможность отказаться от передачи своего местоположения.

4. **Хранение данных**

   Данные пользователей, семейных групп, бюджета, календаря, продуктов, домов и сообщений должны храниться в базе данных.

   После изменения информации актуальное состояние должно сохраняться и быть доступно пользователю при следующем входе.

5. **Простота использования**

   Основные действия — добавление расхода, продукта, события или сообщения — должны выполняться без сложного обучения.

   Пользователь должен понимать назначение основных разделов приложения при первом использовании.

6. **Синхронизация**

   Изменения в общих разделах должны становиться доступны другим членам семьи без необходимости повторного ввода данных.

   Изменения в бюджете, информации о продуктах, календаре и чате должны корректно отображаться у участников семейной группы.

7. **Разграничение доступа**

   Система должна поддерживать как минимум два типа пользователей: обычный и премиум.

   Обычный пользователь имеет доступ к базовым функциям, но ограничен в использовании геолокации, создания событий, количестве членов семьи и нейросетевой функции подбора рецептов.

   Премиум-пользователь получает доступ к расширенным возможностям приложения.

8. **Локализация**

   Интерфейс и системные сообщения должны быть доступны на русском языке.

   Форматы дат, времени и денежных значений должны соответствовать требованиям русскоязычной аудитории.
